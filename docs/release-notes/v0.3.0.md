# mai2srt v0.3.0

转录队列改成流水线，转录进行中可以继续拖入文件；修复 Linux 版精修页播放没有声音的问题。首次随 Release 提供 Linux 安装包。

## 转录队列

- **流水线执行。** 一个文件的处理分三步：准备（本机 ffmpeg 压缩分块）、上传转录（playground）、断句（大模型）。以前一个文件三步走完才开始下一个；现在三步同时进行——上一个文件在断句时，下一个已经在上传，再下一个在准备。整批用时基本只取决于最慢的那一步。准备最多提前一个文件，临时文件不会堆积。
- **转录中可以继续拖入文件。** 新拖入的音视频会排到队列末尾，已在队列里的会提示并忽略；还没开始的文件可以随时移除。`.mai.json` 仍需等队列结束后再生成字幕。
- **单个文件也走队列。** 只选一个文件时界面和以前一样（阶段时间线、结果卡片），但已有转录结果和字幕的文件默认跳过，那一行有「重新转录」按钮。
- **每一行显示自己的阶段**：准备中 / 等待上传 / 上传转录（含分块进度）/ 等待断句 / 断句中。多个文件时显示整体进度条。
- **同时断句的文件数可设置**：设置 → 大模型，默认 1。调高会同时向大模型发起多路请求，限流严格的服务商或本地模型建议保持 1。
- 断句前转录结果已经写入项目库，所以断句失败或中途取消不会浪费上传；遇到登录失效、生物特征通知（HTTP 451）等全局问题时，停止后续上传，已经上传完的文件仍会断句、生成字幕。

## 命令行

- `mai2srt batch` 同样按流水线执行。`--jobs` 仍是并行上传数（上限 3）；新增 `--llm-jobs N` 设定同时断句的文件数（默认取桌面应用里的设置，上限 4）。

## Linux

- 修复精修页点击播放没有声音。Linux 版界面由 WebKitGTK 渲染、GStreamer 解码音频；系统只装了 GStreamer 基础插件时（Ubuntu 默认安装、AppImage 打包的也是这两套）没有 AAC 解码器，而大多数视频的音轨是 AAC，之前的音频缓存是原样转封装的 `.m4a`，所以无法播放。现在 Linux 上视频音轨和 `.m4a` / `.aac` 文件会转成 mp3 放进音频提取缓存；旧的 `.m4a` 缓存会被忽略并替换，第一次打开时多等几秒。Windows 不受影响，仍是无损转封装。
- 本版起 Release 附带 x86_64 的 `.deb` 与 `AppImage`（构建基线 Ubuntu 22.04）。

## 安装

- **Windows**：下载 `mai2srt_0.3.0_x64-setup.exe`，可以直接覆盖安装，FFmpeg 已随包内置。首次安装可能出现 Windows SmartScreen 蓝窗（安装包未签名）→ 点「更多信息」→「仍要运行」。
- **Linux**：`.deb` 用 `sudo apt install ./mai2srt_0.3.0_amd64.deb` 安装（会一并安装 FFmpeg）；AppImage 需要系统已有 FFmpeg（`ffmpeg`、`ffprobe` 在 `PATH` 中）和 WebKitGTK 4.1 运行库，`chmod +x` 后直接运行。

附件中的 `SHA256SUMS.txt` 可用于校验下载是否完整。

## English

The transcription queue becomes a pipeline you can keep dropping files onto, and the refine page's play button in the Linux app has sound again. First release with Linux installers.

## Transcription queue

- **Pipelined.** A file goes through three steps: preparing (local ffmpeg compression and chunking), uploading (the playground) and segmenting (the LLM). A file used to finish all three before the next one started; now they run side by side — while one file is segmented the next uploads and the one after is prepared, so a batch takes about as long as its slowest step. Preparation runs at most one file ahead, so temporary files do not pile up.
- **Keep dropping files while it runs.** Audio and video dropped during a transcription join the end of the queue; a file already in it is ignored with a notice, and a file that has not started can still be removed. A `.mai.json` still waits until the queue ends.
- **One file is a queue too.** A single file looks as before (stage timeline, result card), but a file that already has a transcript and subtitles is skipped by default and its row offers "re-transcribe".
- **Each row names its own phase**: preparing / waiting to upload / uploading (with the chunk counter) / waiting to segment / segmenting. Several files show one overall progress bar.
- **Configurable LLM concurrency**: Settings → LLM, default 1. Higher values send several LLM requests at once; keep 1 for strictly rate-limited providers or a local model.
- The transcript is saved before segmentation, so a segmentation failure or a cancel never wastes the upload. On a problem that would sink every file (expired sign-in, the biometric notice / HTTP 451) further uploads stop, and files already uploaded still get their subtitles.

## Command line

- `mai2srt batch` runs as the same pipeline. `--jobs` is still the number of parallel uploads (max 3); the new `--llm-jobs N` sets how many files are segmented at once (default: the desktop app's setting; max 4).

## Linux

- Fixed the refine page's play button producing no sound. The Linux app renders with WebKitGTK and decodes audio with GStreamer; with only the base GStreamer plugins (a stock Ubuntu install, and what the AppImage bundles) there is no AAC decoder, while most videos carry AAC — and the audio cache was a straight `.m4a` remux, so it could not play. On Linux, video soundtracks and `.m4a` / `.aac` files are now converted to mp3 in the audio extraction cache; an old `.m4a` cache entry is ignored and replaced, with a few seconds' wait on first open. Windows is unchanged and keeps the lossless remux.
- From this release on, x86_64 `.deb` and `AppImage` installers are attached (built on Ubuntu 22.04).

## Install

- **Windows**: download `mai2srt_0.3.0_x64-setup.exe`; it installs over the previous version, FFmpeg included. A first install may show the Windows SmartScreen prompt (the installer is unsigned) → "More info" → "Run anyway".
- **Linux**: install the `.deb` with `sudo apt install ./mai2srt_0.3.0_amd64.deb` (pulls in FFmpeg); the AppImage needs FFmpeg (`ffmpeg` and `ffprobe` on `PATH`) and the WebKitGTK 4.1 runtime, then `chmod +x` and run it.

`SHA256SUMS.txt` among the assets lets you verify the downloads.
